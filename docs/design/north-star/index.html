01 / Direction

Run the work,
not the machines.

Dogsled is the console for one developer coordinating coding agents. After time away, they need to see what changed and what only they can decide.

The owner’s loop

Return → decide → resume. Find the next decision without scanning every conversation. Act inside the relevant lead, then get back to your own work.

Success: Name the next decision at a glance, open it in one action, and see a receipt before leaving. No machine choice.

P01

Attention has a real count.

Keep Needs you visible. Count open owner requests, not unread replies or branches that agents must land.

P02

Work is the address.

Group leads by repository and name them by outcome. Dogsled chooses where work runs. Machine names, pane IDs, and routing evidence belong in diagnostics.

P03

Decide where you read.

Open questions and plans inside their lead. Keep its conversation one tab away and keep the other requests in sight.

P04

Show receipts, not guesses.

Queued is not running. Sent is not delivered. A saved copy is not done. Show the evidence for each state.

P05

Let leads do the leading.

Nest workers under their lead and command jobs under the agent that started them. Give a job output and a result, not a chat.

P06

Keep the last good view.

When updates stop, show what is cached and when it was current. Keep safe reads available. Disable actions that cannot be verified.

02 / Speed

Fast enough to trust.

The interface must respond before the work does. These are proposed budgets, not measurements of the current portal.

MomentTargetWhat to measure
Find the next decision≤ 5 sFrom first view to naming the request that needs an answer. No clicks.
Get to the request1 actionFrom any primary screen to the open question or review.
First useful screen≤ 1 sp95 warm open to usable Needs you and the Work overview. Cold open target: ≤ 2.5 s.
Switch leads≤ 100 msp95 input to selection and any saved conversation. A previously unseen lead paints its latest slice within 600 ms p95.
Send or decide≤ 100 msp95 input to a visible pending receipt. Durable acknowledgment has a separate 1 s p95 target.
Reflect a state change≤ 2 sp95 recorded event to visible state or inbox count. This excludes agent runtime.
Expose lost updates≤ 5 sFrom the last expected update signal to a visible stale state. Clear it only after a fresh snapshot.

Measure before changing the portal. Run 50 warm and 50 cold trials at 1440 × 900 on the owner’s desktop. Record fleet size, network and cache state. Use at least three repositories, ten leads and two open requests. Report commands separately from agent startup and execution. Repeat with a paused stream. For the five-second goal, observe five return attempts and report misses separately.

03 / Visual system

The quiet console.

The book uses paper and ink. The product keeps the slate console from DESIGN.md. Color signals a change in state, not decoration.

Type

Use IBM Plex Sans for UI and 15px conversation prose. Use JetBrains Mono for code, time and branch names. This offline edition uses system fallbacks when the fonts are absent.

Space

Use a 4–24px spacing scale, 1px rules, and 4–12px radii. The desktop grid has a 52px bar, 292px work rail, and 300px lead inspector.

Signals

Pair every state color with a label. Use muted steel #9AA3B9 for secondary copy and #222C45 for dividers. Make focus distinct from selection.

Regions

Pin the service bar and action bars. Scroll the rail, transcript, and form inside the viewport. On narrow screens, move the inspector into tabs. Keep Needs you visible.
