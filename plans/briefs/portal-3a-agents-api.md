# Brief: agents API, conversation reader, Herdr event subscription (web portal step 3a)

**Outcome.** `dogsled web` exposes the local Herdr agents as JSON: the list, each agent's conversation read from its transcript, its visible screen, and actions to prompt, send keys and focus; an SSE stream tells the browser when agents change. No UI (step 3b).

**Design.** Plan `plans/web-portal.md`, Approach 3. Server skeleton, guards and `portal-types` come from step 2a (`src/web/mod.rs`, `src/web/board.rs`). Agents come from `probe::agent_list(shell)` (`src/probe.rs`, `Agent` has `pane`, `agent`, `state`, `name`, `transcript`, `cwd`, `repository`). Transcripts: `activity::tail(path)` reads the last 256 KiB newest-first (`src/activity.rs:48`); `activity::latest`/`reply` already understand pi, claude and codex records — follow those parsers. Socket: `herdr_socket::Client::call` (`src/herdr_socket.rs:35`) is one request/one reply with a timeout; Herdr 0.9.5 `events.subscribe` keeps the connection open and streams events (https://raw.githubusercontent.com/herdrdev/herdr/v0.9.5/docs/next/website/src/content/docs/socket-api.mdx). Events are not durable: subscribe first, then re-read. Herdr CLI for actions: `herdr agent prompt <pane> <text>`, `herdr agent send-keys <pane> <key>...`, `herdr agent focus <pane>`, `herdr agent read <pane> --source visible|recent --format text`. Run every CLI call through the `Shell` abstraction (`src/shell.rs`), never `std::process` directly.

**Edits.**

Unit tests with one small fixture each for pi, claude and codex (copy real record shapes from the existing tests in this file).

- New `portal-types/src/agents.rs` (re-export from lib): `AgentView`, `Message`, `Screen { text }`, `PromptRequest { text }`, `KeysRequest { keys: Vec<String> }`, `ActionResult { ok, blocked: bool, error: Option<String> }`.
- New `src/web/agents.rs`: `GET /api/agents`, `GET /api/agents/:pane/conversation?limit=200` (falls back to `herdr agent read --source recent` text as one Assistant message when the agent kind is unknown or there is no transcript), `GET /api/agents/:pane/screen`, `POST /api/agents/:pane/prompt` (Herdr `agent_blocked` → `blocked: true`, nothing sent), `POST /api/agents/:pane/keys` (keys validated against a whitelist: printable single chars, `enter`, `esc`, `tab`, `backspace`, `up/down/left/right`, `ctrl+c`), `POST /api/agents/:pane/focus`, `GET /api/agents/stream` (SSE event `agents` with the list; driven by one shared background subscription to `pane.agent_status_changed`, `pane.agent_detected`, `pane.exited`, `layout.updated`, re-reading `agent_list` on each event, reconnecting with backoff).
- `src/web/mod.rs`: register the routes only.
