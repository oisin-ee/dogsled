# Dogsled as a momokaya-template app

Status: proposed, revision 3. No part of this plan is approved or implemented. Revision 2 had units too large for one
session, no file-level detail, no reconciliation with the self-update release chain, and unverified design guesses. This
revision replaces it.

## Goal

Dogsled becomes a full momokaya-template app, generated by Copier from momokaya-template `v1.9.3` and updated with
`copier update`. It gains:

- a Crux core (`crates/dogsled-core`) that owns the portal's state;
- a Dioxus 0.8 web shell (`apps/web`) that replaces `web/`;
- iOS and Android shells with a "needs you" scope;
- a Loco gateway (`apps/api`) that signs the owner in and forwards to `dogsled serve`;
- the template's dev stack, brand tokens, Maestro E2E, and release workflow.

The CLI, `dogsled serve`, the Herdr sidebar, the Pi extension, the Claude, Codex and Herdr plugins, and self-update keep
their behaviour.

## Decisions

Owner, 2026-11-19:

1. Dogsled adopts the whole template. A reduced "tool" shape is rejected.
2. The Loco API is a fleet gateway. It does not replace the axum API of `dogsled serve`.
3. Phones reach the gateway through the tailnet only. The template's sign-in also applies.
4. The native shells start with the inbox, questions, plan reviews, a message to an agent, and host load.

Lead, 2026-11-19, from the evidence below:

5. **Copier answers.** `project_name = "Dogsled"`, `project_slug = "dogsled"`, `bundle_prefix = "ee.dogsled"`,
   `main_port_base = 9150`, `sign_in = true`, `openfga = false`, `site = false`, `web_frontend = "dioxus"`. 5150, 6150,
   7150 and 8150 are taken by other template apps. 9150–9169 does not include the portal's 7465.
6. **Repository layout.** The binary moves to `apps/dogsled`. The Pi extension and the harness plugin move to
   `packages/pi-dogsled`. The template owns the root `package.json`, so the published `@oisin-ee/pi-dogsled` cannot stay
   there. npm packs only files inside the package directory, so the skill the package ships must live inside it. The
   Claude and Codex marketplaces point at the new plugin path. `herdr-plugin.toml` and `plugin/` stay at the root, where
   `herdr plugin install oisin-ee/dogsled` reads them.
7. **Release chain.** The template's managed `.github/workflows/release.yml` (release-please) replaces Dogsled's
   `release-please.yml`. Dogsled's own `release-please-config.json` sets `"draft": true` and
   `"force-tag-creation": true`. release-please then makes a draft release and its tag. The template's `publish` job
   starts Dogsled's own `publish.yml` on the tag. `publish.yml` starts dist and builds the gateway image. dist sets
   `create-release = false`: it uploads to the draft and undrafts it in `announce`, after npm publishes. Self-update's
   rule "the latest release has every artifact" still holds. dist sets `tag-namespace = "dogsled"`, which renames its
   workflow to `dogsled-release.yml`. With `dispatch-releases = true`, the namespace changes only the file name. The
   template's `acceptance.yml` (`moon run :lint :test :build`, started by the `ci:full` label on the release PR)
   replaces `ci.yml` and `scripts/release-prepare.sh`.
8. **One core, two entrances.** The gateway serves the web shell with sign-in. `dogsled serve` also embeds it on
   loopback, as it does now. The bundle has no build-time addresses: `WEB_API_URL` and `WEB_AUTH_URL` stay unset, so it
   calls the page's origin. The core asks for a session only when the API answers 401. Loopback never answers 401.
9. **Dogsled owns its UI primitives.** The web shell drops `dioxus-primitives` and builds its 24 components without it.
   `dioxus-sdk-time` stays at `0.8.0-alpha.3`. If `dioxus-primitives` publishes a Dioxus 0.8 release before F2 starts,
   F2 uses it.
10. **Gateway deployment.** The gateway, GoTrue, and their two Postgres databases run in k3s in the namespace
    `dogsled`, the way `zoomies` runs. The image goes to `ghcr.io/oisin-ee/dogsled-gateway`. A Tailscale ingress serves
    `https://dogsled.tail10e7b9.ts.net`: `/auth/v1` goes to GoTrue, and every other path goes to the gateway. The gateway
    reaches netcup's `dogsled serve` through a Tailscale Service `svc:dogsled-serve`. netcup declares the Service with
    `services.tailscale.serve` (TCP to `localhost:7465`). The tailnet policy grants only the cluster's egress proxy
    access to it. The gateway sends `Host: 127.0.0.1:7465` and the portal token, so `src/web/guard.rs` does not change.
    The token goes into OpenBao once.
11. **Owner-only sign-in.** Production GoTrue sets `GOTRUE_DISABLE_SIGNUP=true`. A Kubernetes Job invites the owner's
    email through the GoTrue admin API. The gateway also refuses any JWT whose `email` claim is not in
    `[gateway] owners`.
12. **Order against work in flight.** D1 moves every file in the repository. It starts only after the work of
    `portal-owned-work-plan.md` merges. Then no Dogsled feature branch has to be moved across the new layout.

## Design

### Layout after D2

```
apps/dogsled/          the CLI, `dogsled serve`, the sidebar (from src/, tests/, build.rs)
apps/api/              the Loco gateway
apps/web/              the Dioxus 0.8 shell (replaces web/ at S7)
apps/ios/ apps/android/ apps/e2e/
crates/dogsled-contract/  the API types (from portal-types/ at C1)
crates/dogsled-core/      the Crux core
crates/todo-*/ crates/prewalk-*/   unchanged
packages/pi-dogsled/      the Pi extension (from pi/, package.json) and plugins/dogsled/
packages/oisinpi/ pi-guardrails/ pi-prewalk/ pi-tiers/   unchanged
brand/  compose/  plugin/  herdr-plugin.toml  .claude-plugin/  .agents/plugins/
```

### Core

The core is one Crux app. Each feature has a module with its own event, model and view model: `board` (board, hosts,
metrics), `agent` (conversation, composer, screen, keys, focus, close), `activity` (activity, files, workers, settings,
models), `inbox` (inbox, questions), `review`, `lead` (repos, new lead). The root event wraps each feature's event. A
slice adds its variant when it lands.

Effects: `Http` (crux_http), `Stream` (a shell-owned SSE operation through `Command::stream_from_shell`), `Auth`
(the template's `AuthOperation`), `Render`. The shell gives the core its entrance at start: the API origin, and whether
it is the gateway. A 401 reply moves the model to "sign in".

Errors follow template ADR 0001: typed replies in the contract, error copy and recovery in the core.

### Gateway

The gateway forwards each contract route to `svc:dogsled-serve`. It streams the reply body unchanged, so SSE routes stay
open. It adds `Host: 127.0.0.1:7465` and `Authorization: Bearer <portal token>`. It removes the browser's
`Authorization` header, which carries the GoTrue JWT. It answers 401 without a valid JWT and 403 for an email outside
`[gateway] owners`. It serves the web bundle from its image. It has no state of its own beyond Loco's database.

In the dev stack, process-compose starts a disposable `dogsled serve` with `DOGSLED_STATE` and `DOGSLED_CONFIG` under
`target/dev-serve/`, and the gateway forwards to it directly. The template's Caddy gateway serves `/auth/v1`.

The template's `acceptance.yml` runs `moon run :lint :test :build` when the `ci:full` label is on the release PR. Native

## Out of scope

- Herdr sidebar changes, and any change to `spawn`, `run`, custody, or cleanup.
- Portal features beyond parity with `a6dab93` plus the work of `portal-owned-work-plan.md`.
- Native shells beyond the scope of decision 4.

## Risks

1. Dioxus 0.8 is an alpha, and the template pins one alpha exactly.
2. The tailnet now reaches `dogsled serve` through the egress proxy. The token and the tailnet grant are the only guards
   on that hop.
3. D1 moves every file. Work that branches from an older `main` must rebase across the move.
4. Until S7, two web clients exist. A portal change during S1–S6 must land in both.
